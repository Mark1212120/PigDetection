# 猪只目标检测实验手册

## 实验目标与完成状态

比较YOLOv8s、YOLOX-S、Faster R-CNN、RetinaNet、FCOS和RT-DETR-L，在相同单类别数据划分上训练、按统一验证AP选择权重，再统一测试。六模型服务器100轮实验已完成；本手册以当前实际文件和实测记录为依据，不将历史小规模验收或中断训练写作正式结果。

项目实际位置：`D:\Projects\Pig_Detection_test`。当前结果索引：`experiments/final_results.json`。Word仅包含实验设置、对比表及讨论，中文宋体，英文和数字Times New Roman，不含文献引用编号。

## VSCode中的最简运行

打开项目根目录，先激活环境再输入普通Python命令：

```powershell
conda activate pigdet
python train.py
```

默认从头新建本机40轮批次，batch=4、有效batch=4、验证batch=1、seed=42，关闭早停。每种方法完成固定轮次后按验证集最高COCO AP选权重；最佳轮次不同不等于训练预算不同。无自动断点续训，已有完成批次不覆盖。

若只查看已完成服务器结果，打开 `experiments/work_dirs/report/index.html`，不需要运行训练。

## 两套配置及其边界

| 方案 | 轮数 | 训练batch | 有效batch | 设备依据 |
| --- | ---: | --- | ---: | --- |
| 默认本机 local_40 | 40 | 全部4 | 4 | 本机pigdet配置；不保证4GB显存全部可训练 |
| 服务器 server_100 | 100 | 32、16、8、32、16、16 | 32 | 已完成的RTX 3090批次 |

服务器模型顺序为YOLOv8s、YOLOX-S、Faster R-CNN、RetinaNet、FCOS、RT-DETR-L。100轮历史权重保存在work_dirs，当前配置保存在 `configs/server_100/`。在相应显存环境中可运行：

```powershell
python train.py --profile server_100
```

当前入口增加固定batch保护、可视化和明确输出目录，保留相同轮数与batch预算；不声称与历史服务器源码或CUDA随机过程逐位一致。历史执行源码和原生训练配置见 `experiments/provenance/server_recipe/`。各方法微批不同，BatchNorm统计、尾部累计样本数和预处理亦不同，不能将有效batch写成完全等价训练。

## 数据集与固定划分

清洗后1,015张1280×720图片、1,015份VOC XML、9,735个pig框。数字编号分块，分界两侧各隔离20张，得到train 690张/6,577框、val 112张/1,088框、test 133张/1,289框；excluded 80张/781框保留raw。

划分由 `data/splits/` 固定清单控制，不随训练seed重新抽样。编号不等于已验证拍摄时间或独立来源；当前只适用于同场景探索性比较，不能证明新相机、新猪群泛化或无语义近重复。

VOC导出采用xmin/ymin减1、xmax/ymax保留的既定坐标假设，COCO类别为1，YOLO类别为0。所有方法共用同一派生标注，测试不重新分组、不挑选阈值。

## 数据清洗

本机数据位于 `D:\Projects\Pig_Detection_test\data\raw\pig_detection`，其中 `data/` 存放 JPG，`label/` 存放同名 VOC XML。原包共有 2,016 张图片、1,015 份 XML；当前保留 1,015 对文件、9,735 个 pig 标注框，图像分辨率均为 1280×720。

1. 按确认过的清单删除 1,001 张含猪但无同名 XML 的图片，没有将其当作背景负样本。
2. 原 110 组完全重复图片在上述删除中处理完毕：109 组保留有标注版本，另 1 组两张均无标注，全部删除。当前图片 SHA256 均不同；这不证明不存在语义近重复。
3. 将 XML 的 `path` 改为当前真实 JPG 路径、`folder` 改为 `data`。除这两个字段外，类别与框坐标保持不变。

清洗清单与路径修复记录在 `data/audit/`；历史审计仅描述对应时点，XML 路径修改会改变文件哈希。原始图片备份由用户保留的压缩包提供。

## 第一次复现的数据与环境准备

当前电脑的数据、环境和官方初始化权重已存在，无需重新创建。其他复现者需自行提供同版本数据到 `data/raw/pig_detection/data` 与 `label`，并在激活pigdet后按安装说明安装依赖和YOLOX。

已有派生数据无需重建。其他复现者在派生目录尚不存在时执行 `python tools/prepare_detection.py --protocol exploratory --gap 20`；该命令使用相同编号规则导出，已存在的派生目录会被拒绝覆盖。随后检查：

```powershell
python tools/prepare_detection.py --help
python tools/validate_export.py --dataset data/processed/exploratory
python train.py --check
```

依赖重建顺序见README；本机环境位置为 `D:\Python_Resources\Envs\pigdet`，服务器历史环境位置仅保留在原始迁移记录中。

## 训练与最佳权重选择

六模型共用AdamW、初始学习率0.0001、权重衰减0.0005和余弦调度，名义尺寸640，seed=42；原生预处理和损失保留，关闭项目中配置的随机增强。COCO初始化中形状不匹配的单类别检测头重新初始化，实际加载范围以run_manifest为准。

原生四模型的最佳权重为 `best.pt`；YOLOv8s和RT-DETR-L使用每轮统一pycocotools验证AP选择的 `engine/weights/best_coco.pt`，不能以Ultralytics原生fitness对应的best.pt替代。

当前100轮批次的最佳验证轮次为5、3、18、51、25、9；六条完整历史均有100轮。它们是共同100轮预算内的验证选点，没有使用test选checkpoint。

检查六份训练清单status=completed、smoke_only=false、历史100行、最佳权重SHA256与对应test权重哈希一致，确认六模型来自同一划分。旧Linux路径不改写，本机位置由final_results索引映射。原始图像、环境、缓存和大权重不进入公开GitHub。

单次seed=42的结果没有多随机种子方差或显著性检验。100轮后训练损失持续下降而部分验证AP回落，应讨论过拟合风险；不能因为AP50接近98%就忽略高IoU定位差异。
